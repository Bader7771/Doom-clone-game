# VOIDLOCK

Repository: **Doom-clone-game**

VOIDLOCK is a tiny, original retro first-person shooter and learning-oriented custom engine. It uses a CPU raycaster for the 3D scene, uploads the 320×200 framebuffer to OpenGL, and lets SDL3 handle the platform layer. All visual content is generated by the game code; it contains no assets from DOOM or any other commercial game.

## The mission

Escape a locked industrial sector. Search the lower storage wing for the cyan keycard, open the security door, clear the final room, and step onto the cyan exit tile. The exit activates after the enemies beyond the security door are defeated. A run should take roughly 2–5 minutes.

## Dependencies

- A C++20 compiler (Clang, GCC, or MSVC)
- CMake 3.24+
- OpenGL development files
- SDL3 3.2+

SDL3 can be installed system-wide, or CMake can download SDL 3.2.20 automatically (the default). On macOS with Homebrew:

```sh
brew install cmake sdl3
```

On Ubuntu or other Linux systems, install CMake and OpenGL development packages, then either install your distribution's SDL3 development package or allow the CMake fallback to fetch SDL3.

## Build and run

```sh
cmake -S . -B build
cmake --build build -j
./build/voidlock
```

For a system-only/offline build, use `cmake -S . -B build -DVOIDLOCK_FETCH_SDL=OFF` after installing SDL3.

## Controls

| Input | Action |
|---|---|
| W A S D | Move |
| Mouse | Look |
| Left Shift | Run |
| Left mouse / Space | Fire shotgun |
| E | Open the cyan locked door (key required) |
| Escape | Quit |

Pickups activate on contact. The green canister restores health, the amber box adds shells, and the cyan device is the keycard.

## Project structure

```text
src/
  core/       application lifetime and game loop
  renderer/   raycaster, sprites, weapon, and HUD
  game/       shared math/types
  world/      tile map, collision, door, line-of-sight
  entities/   player and Warden Orb enemy
  weapons/    shotgun timing and hitscan damage
  ai/         reserved for expanded AI behaviors
  input/      SDL event and keyboard state
  audio/      placeholder sound hooks
assets/
  textures/ sprites/ sounds/ maps/  expansion points
```

The map is deliberately stored as readable ASCII in `Level.cpp`, making it easy to learn from and replace with a file loader later. `Renderer.cpp` contains the software framebuffer and small procedural sprites. Audio methods are wired into weapon and pickup events but intentionally silent until original `.wav` assets are added.

## Good next steps

Move the ASCII map into `assets/maps`, load original PNG/WAV assets, replace the fixed-function presentation quad with a small shader, add navigation around corners, and split procedural sprite drawing into a reusable animation/asset system.
